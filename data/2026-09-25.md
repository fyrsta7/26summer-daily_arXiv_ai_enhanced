### [1] [CART: Closed-Loop Adaptive Red Teaming for Large Language Models](https://arxiv.org/abs/2609.27336)
*Dongdong Zhang,Tengchao Lv,Yilin Jia,Yuzhong Zhao,Yupan Huang,Wenshan Wu,Xiangyang Zhou,Shaohan Huang,Nan Yang,Li Dong,Lei Cui,Furu Wei*

Main category: cs.AI



Selection reason: 闭环自适应红队测试框架，含Challenger/Target/Judge角色分离与工具型agent测试，属agent可靠性与安全控制的一般方法，可迁移到coding agent的失败发现与验证机制。

TL;DR: CART 是一个闭环自适应红队框架，通过结果驱动后续测试，在多个评估系列中比静态提示重放发现更多失败和更高风险，并强调角色分离与可审计性。


<details>
  <summary>Details</summary>
Motivation: 静态红队重放固定提示只能衡量已知风险，无法根据测试中发现的失败进行学习，因此需要能够自适应探索弱点的红队方法。

Method: CART 从广泛风险覆盖开始，跟踪新出现的弱点，保持探针多样性，并记录每项发现的证据与来源；它将测试生成者 Challenger、被测 Target（文本模型或受限工具使用智能体）和评估者 Judge 分离。每次测试结果用于指导下一轮测试。

Result: 在 Frontier、JAH 和 Agentic 三个评估系列中，对每个有基线的 Target，CART 均比静态种子重放发现更多失败和更高平均风险，且增益扩展到工具介导的智能体测试；Challenger-Judge 选择会影响所揭示的证据。

Conclusion: CART 将红队从一次性检查清单转变为持续、自适应且可审计的模型与智能体弱点搜索，同时表明需要角色分离和独立审查。结果反映测试策略的发现，而非真实部署中的失败频率。

中文摘要：自动化红队通常重放一组固定的提示，这可以衡量已知风险，但无法从测试期间发现的失败中学习。我们提出 CART（闭环自适应红队，Closed-Loop Adaptive Red Teaming），一个利用每次结果来指导其下一步测试内容的框架。CART 从广泛的风险覆盖开始，跟踪浮现出的弱点，保持新探针的多样性，并记录每项发现的证据和来源。它将创建测试的 Challenger、被测试的 Target（可能是纯文本模型或有边界的工具使用智能体）以及评估结果的 Judge 分离，从而可以独立研究这些角色。在三个评估系列（Frontier、JAH 和 Agentic）中，对于每个有可用基线的 Target，CART 都比静态种子重放发现更多失败和更高的平均风险。增益也扩展到工具介导的智能体测试，表明情境自适应可以揭示直接提示重放无法触及的弱点。这些结果描述的是测试策略发现了什么，而不是失败在真实部署中发生的频率。我们还发现，Challenger-Judge 的选择会影响所揭示的证据，凸显了角色分离和独立审查的必要性。总体而言，CART 将红队从一次性检查清单转变为对模型和智能体弱点的持续、自适应且可审计的搜索。

Original abstract: Automated red teaming often replays a fixed set of prompts, which measures known risks but cannot learn from failures found during testing. We present CART (Closed-Loop Adaptive Red Teaming), a framework that uses each result to guide what it tests next. CART begins with broad risk coverage, follows weaknesses that emerge, keeps new probes diverse, and records the evidence and source of every finding. It separates the Challenger that creates tests, the Target being tested, which may be a text-only model or a bounded tool-using agent, and the Judge that evaluates the results, allowing these roles to be studied independently. Across three evaluation families (Frontier, JAH, and Agentic), CART discovers more failures and higher average risk than static seed replay for every Target with an available baseline. The gains extend to tool-mediated agent tests, suggesting that contextual adaptation can reveal weaknesses that direct prompt replay does not exercise. These results describe what the test policies discover, not how often failures occur in real deployments. We also find that Challenger-Judge choices affect the evidence uncovered, highlighting the need for role separation and independent review. Overall, CART turns red teaming from a one-time checklist into a continuous, adaptive, and auditable search for model and agent weaknesses.

### [2] [Can LLMs Reason About Runtime Behavior? A Repository-Level Dynamic Benchmark](https://arxiv.org/abs/2609.28449)
*Hamed Taherkhani,Mohammad Abdollahi,Melika Sepidband,Hridya Dhulipala,Tien N. Nguyen,Hadi Hemmati*

Main category: cs.SE



Selection reason: 提出仓库级动态执行推理基准 SWE-Flux，用插桩测试自动采集真值，覆盖控制流、数据流、异常与程序状态，可直接用于评测 coding agent 的运行时行为推理能力，属可迁移的软件工程评测资源。

TL;DR: SWE-Flux是仓库级动态执行推理基准，含12个真实Python仓库的480个实例，答案由插桩执行自动收集；评估五个LLM，最佳仅37%，局部行为较好，数据流/过程间/状态推理/套件聚合较弱；输入扰动可为近90%实例生成有效且更难变体。


<details>
  <summary>Details</summary>
Motivation: 现有仓库级问答基准侧重静态代码理解且依赖LLM评估，执行推理基准多限于片段或函数；需评估LLM对代码执行的推理能力。

Method: 构建SWE-Flux，480个执行相关实例，12个Python仓库，覆盖控制流、循环、程序状态、数据流、异常、不变量，单/多测试问题；黄金答案从插桩测试执行自动收集；评估五个LLM；用输入扰动生成变体。

Result: 最佳模型准确率37%；局部行为（不变量、过程内控制流、异常、简单循环）表现较好，数据流、过程间执行、精确状态推理、套件级聚合较弱；扰动流水线为近90%选定实例收集有效变体，变体更难。

Conclusion: LLM在动态执行推理上仍面临挑战；自动收集流程可生成有效且更具挑战性的基准变体。

中文摘要：大型语言模型（LLMs）正越来越多地用于编码任务，但它们对代码执行进行推理的能力仍不清楚。现有的仓库级问答基准主要评估静态代码理解，并且通常依赖基于LLM的评估，而执行推理基准大多局限于代码片段或函数。我们提出了SWE-Flux，一个用于动态执行推理的仓库级基准，包含跨12个真实Python仓库的480个以执行为基础的实例，其黄金答案是从插桩测试执行中自动收集的，而不是手动编写或由LLM评判。该基准涵盖关于控制流、循环、程序状态、数据流、异常和程序不变量的单测试和多测试问题。对五个LLM的评估表明，该任务仍然具有挑战性。最佳模型仅达到37%的准确率。模型在局部化行为上表现更好，例如不变量、过程内控制流、异常和简单循环，但在数据流、过程间执行、精确状态推理和套件级聚合方面表现不佳。最后，我们展示了oracle-harvesting流水线可以使用输入扰动生成新的基准变体。它成功为近90%的选定实例收集到有效变体，并且生成的变体对受评估模型来说具有显著更大的挑战性。

Original abstract: Large language models (LLMs) are increasingly used in coding tasks, but their ability to reason about code execution remains unclear. Existing repository-level QA benchmarks mainly evaluate static code understanding and often rely on LLM-based evaluation, while execution-reasoning benchmarks are mostly limited to snippets or functions. We introduce SWE-Flux, a repository-level benchmark for dynamic execution reasoning containing 480 execution-grounded instances across 12 real Python repositories, with gold answers automatically harvested from instrumented test executions rather than written manually or judged by LLMs. The benchmark covers singletest and multi-test questions over control flow, loops, program state, dataflow, exceptions, and program invariants. Evaluating five LLMs shows that this task remains challenging. The best model achieves only 37% accuracy. Models perform better on localized behavior such as invariants, intra-procedural control flow, exceptions, and simple loops, but struggle with dataflow, inter-procedural execution, precise state reasoning, and suite-level aggregation. Finally, we show that the oracle-harvesting pipeline can generate fresh benchmark variants using input perturbation. It successfully harvests valid variants for almost 90% of the selected instances, and the resulting variants are substantially more challenging for the evaluated models.
