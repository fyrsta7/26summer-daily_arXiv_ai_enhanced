Kubernetes repairs reach near-perfect rates for commercial models but require verification-guided iteration for the open-source model. Structured prompting consistently reduces Terraform repair quality, challenging common assumptions about constrained LLM output. The benchmark and artifacts are released for reproducibility.

### [3] [Soundness Checking of Taint Flow Models](https://arxiv.org/abs/2609.28750)
*Samarth Kishor,Victor Nicolet,Joey Dodds*

Main category: cs.SE



Selection reason: LLM agent 生成污点流模型并用符号算法递归验证其可靠性，是“LLM 生成+形式化验证”的典型范式，与程序分析正确性、agent 输出验证高度相关。

TL;DR: 提出猜测-检查方法：LLM生成方法污点流模型，符号算法验证其健全性；在6个大型Go代码库的97个模型上，93%覆盖方法被证明健全，且无新增误报。


<details>
  <summary>Details</summary>
Motivation: 现有静态污点流分析依赖用户手动提供精确的库方法模型，但手动建模繁琐且可能不健全；而通过过程间污点分析自动建模又可能效率低下。

Method: 该方法包含两部分：（1）LLM代理生成方法的精确污点流模型；（2）符号算法检查模型健全性，推断必须不发生的污点流，并用类型系统、指针分析等轻量级静态分析证明；当不足时，推断最大通用被调用者模型并递归验证，避免完整过程间分析。

Result: 在6个大型Go代码库的97个LLM生成污点流模型上评估，证明模型对其覆盖的93%方法健全；这些健全模型也精确，证明污点流属性时未引入新误报。

Conclusion: 猜测-检查方法能高效生成并验证精确、健全的库方法污点流模型，减少手动建模负担，并在多数情况下避免完整过程间污点分析。

中文摘要：针对命令式编程语言的现有最先进静态污点流分析，通过使用由用户提供的精确库方法污点流模型，可以扩展到大型应用。然而，手动且精确地建模一个方法的污点流既繁琐又可能不健全。此外，通过过程间污点分析来自动建模该方法可能效率低下。为了解决这个问题，我们提出一种猜测-检查方法：（1）一个LLM代理，用于生成方法的精确污点流模型；（2）一个符号算法，用于检查该模型的健全性。该算法推断，为使LLM的污点流模型健全，哪些污点流必须不能在该方法中发生，并使用轻量级静态分析（例如类型系统和指针分析）来证明这些禁止流。当这些分析不足时，该算法推断最大通用的被调用者模型，并递归验证其健全性，从而在大多数情况下避免完整的过程间污点分析。由于更精确的模型需要验证的禁止流更少，LLM模型的精度直接决定了我们方法的效率。我们在6个大型Go代码库中的97个由LLM生成的方法污点流模型上评估了我们的方法，并证明这些模型对其覆盖的93%的方法是健全的。被证明健全的LLM生成模型也是精确的，在证明污点流属性时不会引入新的误报。

Original abstract: Existing state-of-the-art static taint flow analyses for imperative programming languages can scale to large applications by using precise user-provided taint flow models of library methods. However, manually and precisely modeling a method's taint flows is tedious and potentially unsound. Furthermore, automatically modeling the method via an inter- procedural taint analysis can be inefficient. To solve this problem, we propose a guess-and-check approach: (1) an LLM agent that generates a precise taint flow model of a method and (2) a symbolic algorithm to check the soundness of the model. The algorithm deduces which taint flows must not occur in the method for the LLM's taint flow model to be sound, and uses lightweight static analyses (e.g., type system and pointer analysis) to prove these must-not-flows. When these analyses are insufficient, the algorithm deduces maximally-general callee models and recursively verifies their soundness, avoiding a full inter-procedural taint analysis in most cases. Since a more precise model requires fewer must-not-flows to be verified, the precision of the LLM's model directly determines the efficiency of our approach. We evaluate our approach on 97 LLM-generated taint flow models for methods in 6 large Go codebases and prove the models sound for 93% of the methods they cover. The proven-sound LLM-generated models are also precise, resulting in no new false-positives when proving taint flow properties.
