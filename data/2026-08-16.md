Main category: cs.AI



Selection reason: 针对大有限集合的约束解码加速，保证输出有效性并大幅提升吞吐，对 coding agent 的结构化输出与校验有直接启发。

TL;DR: 提出trie自动机机制，利用有限集合结构预计算token掩码，显著提升受限解码的速度和吞吐量，在批量服务中相比XGrammar实现29倍吞吐量提升，并保证输出有效性。

  <summary>Details</summary>
Motivation: 现有的受限解码系统在处理有限字符串集合选择时，依赖通用语法编译，当有效值数量达到数千时会出现性能急剧下降的“基数墙”，导致速度过慢，无法满足大规模应用需求。

Method: 引入trie自动机，利用Aho-Corasick多模式匹配挖掘有限集合的共享前缀、有界深度和已知基数等结构，预计算每个节点的token掩码，从而绕过引导解码管道，实现无状态服务路径。

中文摘要：大语言模型日益需要生成符合预定义模式的结构化输出，其中一个常见约束是从有限的有效字符串集合中进行选择。当前的受限解码系统通过通用语法编译来处理这一问题，但随着有效值数量增长到数千，这种方法的性能会急剧下降，即所谓的“基数墙”。我们引入了trie自动机，这是一种专门的机制，通过Aho-Corasick多模式匹配利用有限集合的结构（共享前缀、有界深度、已知基数）来预计算每个节点的token掩码。与XGrammar（vLLM和SGLang中的主要后端之一）相比，trie在每步有效token计算上实现了7倍的加速（0.65微秒对比5.8微秒），并且在K≥300时编译速度提升2至6.5倍。由于预计算的掩码能够实现绕过引导解码管道的无状态服务路径，这一优势在批量服务中进一步放大：在批量大小为256时，端到端的vLLM吞吐量达到219请求/秒，而XGrammar为7.5请求/秒（29倍）。这29倍的提升结合了算法加速和仅预计算掩码才能解锁的集成路径节省。在七个tokenizer系列（32K至262K词汇量）中，trie在K=10,000时保持低于100毫秒的编译时间，且每步成本与集合大小无关，同时保证100%的输出有效性。

Because precomputed masks enable a stateless serving path that bypasses the guided decoding pipeline, this advantage compounds in batch serving: end-to-end vLLM throughput reaches 219 req/s vs. XGrammar's 7.5 req/s at batch size 256 (29X). The 29X combines the algorithmic speedup with integration-path savings that only precomputed masks can unlock. Across seven tokenizer families (32K--262K vocabulary), the trie maintains sub-100ms compilation up to K = 10,000 and flat per-step cost regardless of set size, while guaranteeing 100% output validity.
